# Начни здесь — BudgetBranch / Codex (v2)

Это **обновлённый комплект планирования**, а не готовый код. Старые файлы из v1 целиком заменяются соответствующими файлами v2. Дополнительные файлы `MODEL_ROLES_RU.md` и `PROMPTS_WORKERS_RU.md` нужны для правильной конфигурации моделей и при невозможности прямого назначения субагентам.

## Какие модели выбирать

- **Главный интегратор:** GPT-6 Astra, effort **Max**.
- **Contract Engineer:** GPT-6 Astra, effort **Max**.
- **Independent Security QA:** GPT-6 Astra, effort **Max**.
- **SDK / Agents:** GPT-6.1 Sol, effort **Max**.
- **Frontend:** GPT-6.1 Sol, effort **Max**.
- **Integration Tests / CI:** GPT-6.1 Sol, effort **Max**.

## Порядок запуска

1. Создай локальную **новую** папку проекта BudgetBranch и репозиторий Git (или используй новый существующий пустой репозиторий).
2. Распакуй сюда **все файлы из этого архива** (корень файлов — корень репозитория, не ещё одна вложенная папка). Открой папку в Codex.
3. Выбери **Astra 6 / Max**, запусти новый поток и передай полный текст `PROMPT_INTEGRATOR_RU.md`.
4. На стадии M0 интегратор создаст `SPEC.md` и отчёт **G0**. Покажи их владельцу/в чате и утверди или верни доработать.
5. Только после G0 запусти Contract (Astra Max), SDK (Sol Max), UI (Sol Max); затем независимый QA (Astra Max) и Integration Tests/CI (Sol Max). При необходимости — отдельные Codex-потоки с промптами из `PROMPTS_WORKERS_RU.md`.
6. Своевременно принимай G1 (денежная логика), G2 (полное демо на Mac), G3 (публикация и конкурсная заявка) по `OWNER_CHECKPOINTS_RU.md`.

**Важно:** текст в промпте сам по себе не переключает модель. Интегратор обязан проверить, способен ли его Codex-режим создавать субагентов с нужными моделями/Max. Если нет — разные модели задаются владельцем для отдельных Codex-потоков.

**Чего не делать сейчас:** публичный push, X, заявка, VPS, домен, Mainnet, настоящие деньги. Всё это либо не требуется, либо возможно только после отдельного разрешения владельца.
